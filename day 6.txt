================================================================================
        3. THE NUMPY 2 FAILURE AND THE PAL PATCH
================================================================================

3.1  Symptom. python part4.py printed, then crashed:
         One or more of the specified properties were not recognized by the
         board-specific driver.
         QArm terminated successfully.
         ValueError: setting an array element with a sequence.
     at pal\products\qarm.py line 159:
         self.writeOtherBuffer[4] = np.clip(gprCMD,0.1,0.9)
     The crash happened before the first write, so the arm received nothing.

3.2  Cause. The lab PC runs Python 3.14.4, which brings numpy 2. numpy 2
     refuses to put a 1-element array into a single buffer slot (numpy 1.25+
     only warned). Our scripts passed the gripper as np.array([0.1]).
     Quanser's own default, gprCMD=np.zeros(1), fails the same way, so
     Quanser's pal is broken on numpy 2 regardless of our code. The co-op
     guide says the libraries need Python 3.10.11, which explains why they
     never saw it.

3.3  First fix (commit 1a0a949, local): pass the gripper as a plain float in
     part4.py and ik_test.py. Verified on numpy 2.3.5 that the array form
     fails and the float form works and still clips (0.95 -> 0.9).

3.4  It still failed on the lab PC. The hand edit had most likely left
     "g = [0.1]" (a list fails the same way). Never fully confirmed.

3.5  Final fix: patched the LOCAL copy of pal (Q-Arm\scripts\pal), lines 159
     and 252:
         np.clip(gprCMD,0.1,0.9)
           -> float(np.clip(np.ravel(gprCMD)[0],0.1,0.9))
     This accepts a float, list or array, including Quanser's defaults. The
     original in C:\ME547 is unpatched. After this, part4.py and ik_test.py
     both ran.

3.6  The "properties were not recognized" line. pal's __init__ tries to set
     PID gains with set_double_property; the arm's firmware did not accept
     them. The arm then runs on its built-in default gains. Quanser's own
     examples call the same code, so they would print the same thing. No
     shaking, overshoot or sluggishness was reported. Cause not
     investigated.
