ISSUE 1 - The DH table contradicted the URDF.
  The table listed L3 as d_3, a translation along the joint-3 axis. Since
  joint 3 is the elbow PITCH, that makes the 50 mm offset point sideways, out
  of the arm's bending plane. The URDF had it in-plane. Two different robots.
  The table also used a_2 = L2, implying a horizontal zero pose, while the
  URDF's zero pose is vertical. The doc already carried a "TODO: verify this

ISSUE 2 - The elbow kink was applied TWICE. (the real bug)
  atan(L3/L2) = atan(0.05/0.35) = 8.13 deg = beta, exactly.
  That is not a coincidence: L3 and beta describe THE SAME mechanical feature.
  But the URDF applied an Ry(beta) rotation on elbow_offset AND a separate
  L3 translation on joint_3.

  Effect: the elbow sat at (0.0495, 0, 0.4929) instead of (0.05, 0, 0.49).
  The effective upper arm was 346.5 mm instead of 353.6 mm - 7.1 mm short.
  The model failed to reproduce Quanser's own Table 2 numbers.

ISSUE 3 - Reach did not match the datasheet.

================================================================================
        3. HOW THEY WERE RESOLVED
================================================================================

Resolved by reading the Quanser manual directly (Figure 3 + Table 2). The
student supplied the figure; no guessing was involved.

FIGURE 3 SHOWS: beta is the angle between L2 (vertical dashed line) and
lambda_2 (the slanted line from shoulder to elbow). L3 is the horizontal
offset at the top of L2. So L2, L3 and lambda_2 form a right triangle:

               elbow axis
                  o
                 /|
                / |   L2 = 0.35      <- one Cartesian component
    lambda_2   /  |
    = 0.3536  / b |   b = beta
             o----+
       shoulder    L3 = 0.05         <- the other component
       axis

    lambda_2 = sqrt(L2^2 + L3^2) = 0.353553 m
    beta     = atan(L3 / L2)     = 8.1301 deg

Three descriptions of ONE triangle. Give any two, the third follows. beta is
therefore NOT independent information, which is exactly why typing in both L3
and beta let the URDF double-count the bend.

FIX: apply the kink exactly once. All elbow geometry now lives in a single
place - joint_3's <origin> - which makes a second application structurally
impossible. The old intermediate elbow_offset joint and link_elbow frame are
gone.

REACH (Issue 3) - resolved, and it was NOT a modelling error:

  direction    computed to end_effector    manual    gap
  horizontal   0.753553 m                  0.800 m   0.046447 m
  vertical     0.893553 m                  0.940 m   0.046447 m

The gap is IDENTICAL in both directions. That is the whole argument: a wrong
link length would project differently into horizontal and vertical, so an
identical shortfall can only be a constant length appended at the tip.

CONCLUSION: end_effector is the gripper MOUNTING face. The manual measures
reach to the FINGERTIP, ~46.4 mm further out. L1..L5 are correct as given and
must NOT be adjusted to force the numbers to match.

So the Xacro gained L_gripper = 0.046447 and an ADDITIONAL frame gripper_tip.
end_effector did not move, so the saved RViz config and all prior work stay
valid. Reach to gripper_tip now reproduces 0.800000 / 0.940000 exactly.


================================================================================
        4. EFFECTIVE (LAMBDA) LENGTHS - the key concept
================================================================================

L values     = how a mechanical drawing describes the part.
lambda values = the straight-line distance between consecutive joint AXES.
                This is what a DH chain is actually built from.

They are the same number unless a link is BENT. Only the upper arm is bent.

  Symbol     Definition         Spans                          Value
  lambda_1   L1                 base axis -> shoulder axis      0.140000 m
  lambda_2   sqrt(L2^2+L3^2)    shoulder axis -> elbow axis      0.353553 m
  lambda_3   L4 + L5            elbow axis -> end_effector       0.400000 m

The manual defines THREE lambdas, not four. An earlier revision of our doc
invented lambda_4 = L5; that notation does not exist in Quanser's figure. The
numbers were always identical (0.25 + 0.15 = 0.40 either way), so correcting
it changed no math - only the symbol names, which now match the manual.

WHY lambda_3 CAN SPAN ACROSS JOINT 4:
Figure 3's lambda_3 bracket runs from the elbow axis to the frame-4 origin,
with the wrist-roll joint sitting partway along it at the L4/L5 boundary.
Lumping a translation past a joint is legal in DH only because joint 4 rotates
about the very axis it slides along - the wrist roll is collinear with the
forearm, so L4 and L5 stay parallel no matter what q4 does, and Rz/Tz about a
shared axis commute.

That same collinearity is the reason q4 cannot change end-effector POSITION.
One geometric fact, two consequences. It is also the property that lets IK
split into "solve q1,q2,q3 for position" then "solve q4 for orientation".

"Effective" means: the equivalent simple thing that produces identical motion.
The upper arm is a bent casting, but kinematically it is indistinguishable
from a straight 353.553 mm link permanently tilted 8.13 deg. DH has no
"jog sideways" move, so the bend must be expressed as one straight length
(lambda_2) plus one baked-in angle offset (beta inside theta_2).


================================================================================
        5. CORRECTED DH TABLE
================================================================================

Standard DH convention - the transform from frame i-1 to frame i is ALWAYS
these four moves in this order, with no others permitted:

    T_i = Rot(z, theta_i) * Trans(z, d_i) * Trans(x, a_i) * Rot(x, alpha_i)
            rotate about z   slide along z  slide along x   twist about x

There is no translate-along-y and no rotate-about-y. That ban is the source of
every strange constant below.

DERIVATION (not guessed). Because (L3, 0, L2) = lambda_2 * (sin b, 0, cos b):

    T(L3, 0, L2) = Ry(beta) Tz(lambda_2) Ry(-beta)

Substituting that into the URDF chain, the Ry(-beta) cancels the structural
Ry(beta) immediately following it, and Rz/Tz about a common axis commute:

    T = Rz(q1) Tz(lambda_1) Ry(q2+beta) Tz(lambda_2) Ry(q3) Tz(lambda_3) Rz(q4)

Four joints acting on three effective lengths - the DH form:

 i | theta_i           | d_i        | a_i        | alpha_i | meaning
---+-------------------+------------+------------+---------+------------------
 1 | q1                | lambda_1   | 0          | -pi/2   | base roll
   |                   | = 0.140000 |            |         | joint_1
 2 | q2 + beta - pi/2  | 0          | lambda_2   | 0       | shoulder pitch
   |                   |            | = 0.353553 |         | KINK LIVES HERE
 3 | q3 + pi/2         | 0          | 0          | +pi/2   | elbow pitch
   |                   |            |            |         | no beta - spent
 4 | q4                | lambda_3   | 0          | 0       | wrist roll
   |                   | = 0.400000 |            |         |

WHY THE alpha COLUMN IS WHAT IT IS - the single rule:
  "z of frame i must point along joint i+1's axis."
alpha exists for no other purpose. You do not choose it; you read it off the
hardware.

  joint 1 axis = Z, joint 2 axis = Y   -> perpendicular, need 90 deg twist.
      Rx(-90) sends z -> +y;  Rx(+90) sends z -> -y.
      Joint 2's axis points along +Y, so alpha_1 = -pi/2.
      (The minus sign is what avoids a sign flip on q2.)
  joint 2 axis = Y, joint 3 axis = Y   -> parallel, alpha_2 = 0.
  joint 3 axis = Y, joint 4 = roll down the forearm -> alpha_3 = +pi/2.
  nothing after joint 4               -> alpha_4 = 0.

  alpha = (-pi/2, 0, +pi/2, 0)  <- a direct transcription of "roll pitch
                                    pitch roll". Not a design choice.

WHY theta_2 HAS THREE TERMS:
    theta_2 = q2  +  beta  -  pi/2
               |      |        |
               |      |        +-- bookkeeping: DH only rotates about z, but
               |      |            the shoulder physically pitches about y.
               |      |            After alpha_1 twisted the frame, x no
               |      |            longer points down the arm. This re-aims
               |      |            it. The robot never moves through it.
               |      +----------- PHYSICAL: the 8.13 deg structural bend.
               |                   Rides inside theta forever because DH
               |                   cannot express a sideways jog. Applied
               |                   exactly ONCE, here.
               +------------------ the real joint variable.

theta_3 = q3 + pi/2 has no beta, because beta was already spent in row 2.
Applying it again reintroduces the original bug.

d VERSUS a - same length, different direction:
  d slides along z = along the joint axis
  a slides along x = perpendicular to it
  Row 1 uses d: climbing L1 runs ALONG the base roll axis.
  Row 2 uses a: the upper arm sticks out SIDEWAYS from the pitch axis.
  Row 4 uses d: the tool runs ALONG the wrist roll axis - which is precisely
                why q4 cannot move the gripper. Rotating about an axis and
                then travelling along that same axis leaves you in the same
                place.

PROOF, not assertion: test_dh_matches_urdf_chain multiplies out the URDF
origins directly and compares against this table over 200 random in-limit
poses. Agreement within 1e-12.

  end_effector  translation = [0.106569, 0.000000, 0.885980] m

  x = L3 + (L4+L5)*sin(beta) = 0.05 + 0.40*0.141421 = 0.106569   OK
  z = L1 + L2 + (L4+L5)*cos(beta) = 0.49 + 0.40*0.989949 = 0.885980   OK

SUPERSEDED: the old value [0.106, 0.000, 0.879] came from the double-counted
URDF. The 7 mm z error is the lost effective upper arm projected vertically.

The 8.13 deg pitch is correct in both: at the zero pose the only rotation left
anywhere in the chain is beta.

the reviewer's hand substitution, and a separate hand computation.
